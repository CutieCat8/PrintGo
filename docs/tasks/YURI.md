# งานของยูริ (สัฏฐี) — Frontend

อ่าน `CLAUDE.md`, `docs/CONTRACTS.md`, `DECISIONS.md` ก่อนทุก task · ถามก่อนทำตามโปรโตคอลใน `CLAUDE.md` ข้อ 1
โฟลเดอร์ของยูริ: `src/app/liff/**`, `src/app/shop/**` (ยกเว้น `shop/settings/**` ของอาร์ม), `src/app/dev/**`, `src/app/globals.css`, `src/app/not-found.tsx`, `src/app/error.tsx`, `src/components/ui/**`, `src/lib/client/**` (ตัวเรียก API ฝั่ง client + mock)

## หลักการออกแบบ (ใช้กับทุก task)
- **หน้าลูกค้า: mobile-first** เปิดใน LINE (กว้าง ~360–430px), ปุ่มสูงอย่างน้อย 44px, ตัวอักษรเนื้อหา ≥ 16px
- **หน้าร้าน: เดสก์ท็อป/แท็บเล็ต** ร้านเปิดที่เคาน์เตอร์ ตัวใหญ่ อ่านเร็ว ปุ่มหลักเด่นหนึ่งปุ่มต่อสถานะ
- สี: navy `#12284C` (หลัก), ส้ม `#F26B21` (เน้น/ปุ่มหลัก), พื้นขาว/เทาอ่อน · ห้ามใช้เขียวเป็นสีหลัก
- ข้อความบนหน้าจอเป็นภาษาไทยเข้าใจง่าย ไม่ใช้ศัพท์เทคนิค ("ชำระเงิน" ไม่ใช่ "payment")
- **ทุกหน้าต้องมี 4 สถานะ:** กำลังโหลด (skeleton), ข้อมูลว่าง, ผิดพลาด (ข้อความไทย + ปุ่มลองใหม่), ปกติ
- เงินแสดงผ่าน `formatBaht()` เท่านั้น (`฿1,250.50`); **ห้ามคำนวณราคาในหน้าจอ** ใช้ค่าที่ API คืน (ยกเว้นผลรวมแสดงผลที่ API ไม่ได้ให้ — ถามก่อน)
- ข้อความจากผู้ใช้ (หมายเหตุ/แชท/ชื่อไฟล์) แสดงเป็น text เสมอ ห้าม `dangerouslySetInnerHTML`
- ข้อมูลตัวอย่างใน mock ต้องติดป้าย "ตัวอย่างสมมติ" และไม่ใช้ข้อมูลจริงของคน/ร้าน

## Y2 — ชั้นเรียก API + Mock (ทำให้ไม่ต้องรอพลุ)  ·  10 พ.ย.
**เป้าหมาย:** เขียนหน้าได้ทันทีด้วยข้อมูลจำลองที่ตรงสัญญา แล้วสลับเป็น API จริงได้ด้วยตัวแปรเดียว
**ไฟล์:** `src/lib/client/api.ts`, `src/lib/client/mock/*`, `src/lib/client/hooks/*`
**ทำอะไร:**
- ฟังก์ชันเรียก API ทุกตัวตาม CONTRACTS ข้อ 6.1–6.3 (ลูกค้า/ร้าน/ชำระเงิน — ใช้โดยหน้าของยูริและ `PaymentPanel`/หน้าตั้งค่าของอาร์ม; กลุ่มแอดมิน 6.4 อาร์มเขียนเองใน `src/app/admin/_lib/api.ts`) (ชื่อฟังก์ชัน/พารามิเตอร์/ชนิดผลลัพธ์ใช้ type จาก `db/types` เมื่อ Z2 เสร็จ) เช่น `listShops()`, `estimate()`, `createOrder()`, `getOrder()`, `listShopOrders()`, `confirmOrder()` …
- ถ้า `NEXT_PUBLIC_USE_MOCK=true` ให้ใช้ข้อมูลจำลองที่เก็บในหน่วยความจำ (มีออเดอร์หลายสถานะ, ร้าน 3 ร้านปิด/เปิด/พัก ร้านละ 2–3 บริการเสริม (1 รายการ "ราคาตามตกลง"), delay 300–600ms, จำลอง error บางครั้งได้ด้วย query `?mockError=1`)
- ใส่ `Authorization: Bearer <liffIdToken>` อัตโนมัติ (LIFF) / ใช้คุกกี้สำหรับหน้าร้าน
- hooks ด้วย SWR: `useOrder(id)` (poll ทุก 5 วิเมื่อสถานะยังไม่จบ), `useShopOrders()` (poll ทุก 5–8 วิ), `useMessages(orderId)` (poll ทุก 4 วิ), `useChats()` (poll ทุก 10 วิ ลูกค้า / 5–8 วิ ร้าน; หยุดเมื่อแท็บไม่ visible; คืน `totalUnread` + รายการห้อง)
- แปลง error ตามรูปแบบ CONTRACTS ข้อ 1 เป็นข้อความที่ UI แสดงได้ (`ApiClientError`)
**เกณฑ์ผ่าน:** [ ] เปิด/ปิด mock ด้วย env ได้โดยไม่แก้หน้า [ ] mock คืนค่าตรงชนิดใน CONTRACTS ทุกฟิลด์ [ ] ไม่มีการเรียก `fetch` กระจายในหน้า (ทุกอย่างผ่าน `api.ts`)
**ห้าม:** เดาโครง response (ถ้าสัญญาไม่ครบ ให้ถามซี) · เก็บ token ใน localStorage นานเกิน session

## Y3 — LIFF bootstrap + ฟอร์มสั่งปริ้น  ·  10–11 พ.ย.
**เส้นทาง:** `/liff` (redirect), `/liff/new`
**ทำอะไร:**
- ติดตั้ง `@line/liff` (ถามซีก่อนถ้าเวอร์ชันมีปัญหา), เริ่ม LIFF ด้วย `NEXT_PUBLIC_LIFF_ID`, ถ้ายังไม่ล็อกอินให้ `liff.login()`; ถ้าเปิดนอก LINE (เบราว์เซอร์ทั่วไป) แสดงข้อความ "กรุณาเปิดจากแอป LINE" (โหมด dev ข้ามได้ด้วย mock)
- ฟอร์ม "สั่งปริ้น" ทีละส่วน (ขั้นตอนบนหน้าเดียวเลื่อนลง หรือ stepper ง่าย ๆ):
  1. **เลือกไฟล์** (หลายไฟล์; PDF/JPG/PNG; ≤ 20 MB ต่อไฟล์, ≤ 10 ไฟล์ — ตรวจฝั่ง client พร้อมข้อความไทยแต่ไม่ใช่ที่เดียวที่ตรวจ) · แสดงข้อความแจ้งใต้ปุ่มเลือกไฟล์ (D20): "ร้านที่คุณเลือกจะเปิดและดาวน์โหลดไฟล์เพื่อปริ้นได้ ไฟล์บนระบบเราจะถูกลบภายใน 7 วันหลังจบออเดอร์ แต่สำเนาที่ร้านดาวน์โหลดไปอยู่ในความดูแลของร้าน หากเป็นเอกสารลับไม่ควรส่งผ่านบริการนี้" (ข้อความแจ้ง ไม่ต้องมีช่องติ๊กยอมรับ)
  2. **ตั้งค่าต่อไฟล์:** สี/ขาวดำ, ขนาด (A4/A3), ด้านเดียว/สองด้าน, จำนวนชุด (1–99) และ "ใช้ค่านี้กับทุกไฟล์"
  3. **นับจำนวนหน้า**: PDF ใช้ `pdfjs-dist` (หรือ `pdf-lib`) นับ **ฝั่ง client** (โหลด worker แบบ lazy) · รูปภาพ = 1 หน้า · นับไม่ได้ → ให้ลูกค้ากรอกเอง (แจ้งว่าร้านจะตรวจอีกครั้ง) · ถ้า pdf.js แจ้งว่าไฟล์มีรหัสผ่านหรือไฟล์เสีย → ขึ้นคำเตือน "ไฟล์นี้อาจมีรหัสผ่านหรือเปิดไม่ได้ ร้านอาจปริ้นให้ไม่ได้" แต่ยังให้ไปต่อได้ (ร้านจะคุยแจ้งผ่านแชท) · ส่งเป็น `pageCount` ตามสัญญา
  4. **หมายเหตุ** (ตัวอักษร ≤ 500)
- อัปโหลดไฟล์: เรียก `POST /uploads/sign` → อัปโหลดตรงเข้า Supabase Storage ด้วย signed URL (แสดง progress ต่อไฟล์, ลองใหม่ได้, ลบไฟล์ออกได้)
- เก็บข้อมูลฟอร์มที่กรอกไว้ใน state/`sessionStorage` ระหว่างขั้นตอนถัดไป (กันหายเมื่อสลับแอป) ล้างเมื่อส่งสำเร็จ
- ปุ่ม "ถัดไป: เลือกร้าน" ปิดไว้จนกว่าไฟล์ครบ อัปโหลดเสร็จ และตั้งค่าถูกต้อง
**เกณฑ์ผ่าน:** [ ] ส่งหลายไฟล์ได้ พร้อมตั้งค่าต่อไฟล์ [ ] ไฟล์ใหญ่/ชนิดผิดแสดงข้อผิดพลาดชัดเจน [ ] นับหน้า PDF ถูก (ทดสอบกับ PDF 1 หน้า และหลายหน้า) [ ] ใช้งานได้บนจอ 360px [ ] ไม่ส่งไฟล์ผ่าน API ของเรา (ผ่าน signed URL เท่านั้น)
**หมายเหตุ (D22):** บริการเสริม (เข้าเล่ม/ปกใส ฯลฯ) ไม่ได้อยู่ในขั้นนี้ เพราะเป็นของแต่ละร้าน ให้เลือกที่ Y4 หลังเลือกร้าน · **ถามก่อนถ้า:** อยากเพิ่มตั้งค่าอื่นนอกเหนือจากนี้ — default: ไม่มี

## Y4 — เลือกร้าน + วิธีรับ + สรุป + ส่งออเดอร์  ·  11–12 พ.ย.
**เส้นทาง:** `/liff/new/shop`, `/liff/new/summary`
**ทำอะไร:**
- ขอตำแหน่งผู้ใช้ผ่าน `navigator.geolocation` (อธิบายเหตุผลก่อนขอสิทธิ์ เช่น "เพื่อแสดงร้านใกล้คุณและเรียกไรเดอร์") · **ได้ตำแหน่ง** → ส่ง `lat/lng` ไป `GET /shops` และใช้เป็นจุดส่งถ้าเลือกจัดส่ง · **ไม่อนุญาต/ได้ไม่สำเร็จ** → แสดงรายการร้านโดยไม่มีระยะ (เรียงตามชื่อ) ยังเลือก "รับเองที่ร้าน" ได้ แต่ "ส่งถึงที่" ปิดไว้ (D24) · **ไม่มีช่องให้กรอกพิกัดเอง** [ถามซีก่อนถ้าจะทำอย่างอื่น]
- เรียก `GET /shops?lat&lng` แสดงการ์ดร้าน: ชื่อ, ระยะ "~2.2 กม." (`distanceKm=null` → ไม่แสดงระยะ), ป้าย เปิด/ปิด/พักรับงาน (+ "ปิดเวลา 20:00" หรือ "เปิดพรุ่งนี้ 09:00"), ราคาเริ่มต้น ("เริ่ม ฿1/หน้า"), ป้ายรับจัดส่ง, **ชื่อบริการเสริมของร้าน (chip ไม่เกิน 4 รายการ + "+N")** · ร้านปิด/พักกดเลือกไม่ได้แต่เห็นเหตุผล · **ไม่มีฟิลเตอร์ร้านตามบริการ** (อนาคต)
- เลือกวิธีรับ: **รับเองที่ร้าน** หรือ **ส่งถึงที่** (ฟอร์ม: ชื่อผู้รับ/เบอร์/ที่อยู่/รายละเอียดจุดส่ง เช่น ตึก ห้อง ฝากไว้ที่ไหน; **พิกัดมาจากตำแหน่งปัจจุบันที่ลูกค้าอนุญาตเท่านั้น** → ส่งเป็น `deliveryRecipientName`, `deliveryRecipientPhone`, `deliveryAddress`, `deliveryLat/Lng`) — ปิดตัวเลือกนี้เมื่อร้านไม่รับจัดส่ง หรือลูกค้ายังไม่อนุญาตตำแหน่ง (แสดงเหตุผลชัดเจน + ปุ่ม "ขออนุญาตตำแหน่งอีกครั้ง" + คำแนะนำสั้น ๆ ถ้าเบราว์เซอร์บล็อกถาวร) · แสดงข้อความ "ไรเดอร์จะไปส่งตามตำแหน่งที่คุณอนุญาตตอนนี้และที่อยู่ที่กรอก ถ้าตอนนี้ไม่ได้อยู่ที่จุดส่ง ให้ระบุรายละเอียดในช่องที่อยู่"
- **บริการเสริมของร้านนี้ (D22):** หลังเลือกร้าน ถ้าร้านมีบริการ ขึ้นส่วน "บริการเสริม" แสดงรายการ (ชื่อ, ราคา "฿35/ชุด" หรือ "฿50/ออเดอร์" หรือ "ราคาตามตกลง") ติ๊กเลือกได้ · บริการ "ต่อชุด" มีตัวเลือกใช้กับไฟล์ไหน (ค่าเริ่มต้นทุกไฟล์; ถ้ามีไฟล์เดียวไม่ต้องถาม) · เปลี่ยนร้านแล้วล้างบริการที่เลือก (บริการเป็นของแต่ละร้าน) · ร้านไม่มีบริการ → ซ่อนส่วนนี้ · ส่งเป็น `services:[{serviceId,fileIndexes?}]` ไปกับ `/estimate` และ `/orders`
- เรียก `POST /estimate` (ส่ง `deliveryLat/Lng` เมื่อเลือกจัดส่ง) เมื่อเลือกร้าน/วิธีรับ/บริการ แสดง: ค่าปริ้นประมาณ, บริการเสริมทีละบรรทัด (`serviceLines`: ชื่อ × จำนวนชุด × ราคา; ราคาที่ร้านยังไม่ตั้งแสดง "ราคาตามตกลง"), ค่าบริการ, ค่าส่ง (ป้าย "ค่าประมาณ"), รวม · ถ้า `requiresManualPrice` แสดงข้อความ "ออเดอร์ขนาดใหญ่ ร้านจะแจ้งราคาให้เร็ว ๆ นี้" (หลังสั่งแล้วหน้าออเดอร์นับถอยหลังจาก `responseDeadline` ห้ามฮาร์ดโค้ดจำนวนนาที) และ **ไม่แสดงตัวเลขที่เป็น null** 
- หน้าสรุป: ไฟล์ทั้งหมด+ตั้งค่า, ร้าน, วิธีรับ, หมายเหตุ, ราคา/ข้อความข้างบน, ปุ่ม "ส่งให้ร้านยืนยัน" (กดซ้ำไม่ได้ ระหว่างส่ง disable) → `POST /orders` → ไปหน้า `/liff/orders/{id}`
- จัดการ error เด่น ๆ: `SHOP_CLOSED`/`SHOP_PAUSED` (กลับไปเลือกร้านใหม่), `VALIDATION_ERROR` แบบ "ร้านนี้ไม่รับงานชุดค่านี้" (บอกว่าไฟล์/ชุดไหนไม่รองรับ + ให้เลือกร้านอื่น), network
**เกณฑ์ผ่าน:** [ ] ร้านปิด/พักเลือกไม่ได้ [ ] manual price ไม่แสดงตัวเลขที่เป็น null [ ] ส่งซ้ำ (ดับเบิลคลิก) สร้างออเดอร์เดียว [ ] เปลี่ยนร้าน/วิธีรับแล้วราคาอัปเดต [ ] เลือกบริการแล้วบรรทัดบริการและยอดอัปเดต (mock) [ ] บริการ "ราคาตามตกลง" ไม่แสดงตัวเลข และขึ้นข้อความรอร้านกำหนดราคา [ ] เปลี่ยนร้านแล้วบริการที่เลือกถูกล้าง [ ] ไม่อนุญาตตำแหน่ง → เลือกจัดส่งไม่ได้แต่รับเองได้ และไม่มีช่องกรอกพิกัด [ ] ขอตำแหน่งบนมือถือจริงใน LINE ได้ผลจริง (รายงานผล; ถ้าอุปกรณ์ใดขอไม่ได้ให้แจ้งซี)
**ถามก่อนถ้า:** แผนที่ปักหมุด — ตัดออกจากรอบนี้แล้ว (ดู README)

## Y5 — ติดตามออเดอร์ + ประวัติ + แชท  ·  12–13 พ.ย.
**เส้นทาง:** `/liff/orders`, `/liff/orders/[id]`, (แชทอยู่ในหน้า detail)
**ทำอะไร:**
- รายการ "ออเดอร์ของฉัน" (ใหม่→เก่า, ป้ายสถานะ, ร้าน, ยอด, เวลา)
- หน้า detail: `Timeline` ตามสถานะ (รอร้านยืนยัน → รอชำระ → ชำระแล้ว → กำลังปริ้น → พร้อม → จัดส่ง/รับเอง → เสร็จ), ข้อมูลร้าน (ที่อยู่/เบอร์), รายการไฟล์, **บริการเสริมที่เลือก (ชื่อ/ไฟล์/จำนวนชุด/ราคา)**, สรุปเงิน (ค่าปริ้น/บริการเสริม/ค่าบริการ/ค่าส่ง/รวม), เหตุผลที่ร้านปฏิเสธ (ถ้ามี), นับถอยหลังเวลาที่ต้องชำระ
- **เวลาเสร็จประมาณ (D19):** แสดงเด่นในหน้า detail และการ์ดรายการ: ก่อนจ่ายแบบนับเวลา → "เสร็จประมาณ 15 นาทีหลังชำระเงิน" · แบบตายตัวหรือหลังจ่ายแล้ว → "เสร็จประมาณ พรุ่งนี้ 12:00 น." (เวลาไทย) + หมายเหตุร้าน · เมื่อสถานะ `awaiting_payment` มี 2 ปุ่มชัด **"ตกลง ชำระเงิน"** / **"ไม่เอา ยกเลิก"** และข้อความเตือน "ชำระเงินแล้วยกเลิกเองไม่ได้ หากต้องการเปลี่ยนแปลงให้คุยกับร้านทางแชท" · หลังจ่ายแล้ว **ห้ามมีปุ่มยกเลิก** (ใช้ฟิลด์ `estimatedReadyAt` ที่อัปเดตตามที่ร้านปรับ + ข้อความ system ในแชท)
- ปุ่มตามสถานะ: `awaiting_payment` → ส่วนชำระเงิน (ใส่ `<PaymentPanel />` ของอาร์ม; ก่อนมีให้ใช้ placeholder), `submitted|awaiting_payment` → "ยกเลิกออเดอร์" (ยืนยันก่อน), `ready` (pickup) → แสดง **รหัสรับงานตัวเลข 4 หลักตัวใหญ่ (เช่น 4821)** พร้อมข้อความ "บอกรหัสนี้กับร้านตอนรับงาน" + ที่อยู่ร้าน, ปฏิเสธ/หมดเวลา → "สั่งใหม่กับร้านอื่น" (พาไป `/liff/new` โดยเก็บไฟล์เดิมถ้าทำได้ ไม่ทำก็ได้)
- ลิงก์ติดตามไรเดอร์ถ้า `delivery.trackingUrl` มี, แสดงสถานะ delivery
- แชทกับร้าน (เส้นทาง `/liff/chats` = รายการห้อง, `/liff/chats/[orderId]` = ห้อง; ฝังในหน้า detail ได้ด้วย): รายการข้อความ (ฟองซ้าย/ขวา), ช่องพิมพ์, ส่ง, auto-scroll, poll ตาม `useMessages` · ส่งไม่สำเร็จแสดงลองใหม่ · ข้อความแสดงเป็น text
- **ห้องปิด** (`CHAT_CLOSED` หรือสถานะปลายทาง): แสดงแบนเนอร์ "ออเดอร์นี้จบแล้ว แชทปิดแล้ว" ซ่อนช่องพิมพ์ อ่านย้อนหลังได้
- **badge**: คอมโพเนนต์ `UnreadBadge` (วงกลมแดง, ตัวเลข, "9+" เมื่อเกิน 9, ซ่อนเมื่อ 0) · แถบเมนูล่างของ LIFF (`LiffBottomNav`: สั่งปริ้น / สถานะงาน / คุยกับร้าน) ใส่ badge ที่ "คุยกับร้าน" จาก `totalUnread` และที่การ์ดออเดอร์ใน `/liff/orders` และรายการห้อง · poll `GET /liff/chats` ทุก 10 วิ (เฉพาะตอนแท็บ visible; หยุดตอน `document.hidden`)
- เปิดห้องแล้วเรียก `POST …/messages/read` (เมื่อห้องแสดงอยู่บนจอจริง ไม่ใช่ตอนโหลดอยู่เบื้องหลัง) แล้ว badge ต้องลดลงทันที
- **หมายเหตุ:** Rich Menu ของ LINE (เมนูใหญ่ล่างสุดใน wireframe) เป็นรูป ใส่ badge ไม่ได้ badge อยู่ในหน้า LIFF เท่านั้น ห้ามพยายามทำ badge บน Rich Menu
- ใช้ `useOrder` (poll) เพื่อสถานะเปลี่ยนเองโดยไม่ต้องรีเฟรช
**เกณฑ์ผ่าน:** [ ] ทุกสถานะ 11 แบบแสดงถูกต้อง (ทดสอบด้วย mock) [ ] รหัสรับงานแสดงเฉพาะเมื่อมีค่า [ ] ยกเลิกมีการยืนยัน [ ] แชทส่ง-รับได้ในโหมด mock [ ] badge ขึ้นเมื่อมีข้อความร้านใหม่และหายเมื่อเปิดอ่าน (mock) [ ] ห้องของออเดอร์ที่จบแล้วส่งไม่ได้ [ ] เวลาเสร็จประมาณแสดงถูกทั้งแบบนับเวลาและแบบตายตัว (mock) [ ] หลังจ่ายแล้วไม่มีปุ่มยกเลิก

## Y6 — Shop Dashboard: ล็อกอิน + คิวงาน + รายละเอียดออเดอร์  ·  11–14 พ.ย.
**เส้นทาง:** `/login` (ปรับสไตล์หน้าของซี), `/shop/onboarding`, `/shop` (คิว), `/shop/orders/[id]`
**ทำอะไร:**
- **สมัครร้าน/สถานะร้าน (D23):** เรียก `GET /api/shop/me` ตอนเข้า `/shop/**`: `no_profile` → ไป `/shop/onboarding` (ฟอร์ม: ชื่อร้าน, เบอร์, ที่อยู่, ปุ่ม "ใช้ตำแหน่งปัจจุบัน" เติม lat/lng (ขอสิทธิ์ตอนกดปุ่ม), ติ๊กรับจัดส่ง → `POST /api/shop/register` → ไปหน้าหลัก) · `pending` → แสดงแถบสีเหลืองทุกหน้า "ร้านของคุณรอแอดมินอนุมัติ — ตั้งเวลาเปิด-ปิด ราคา และบริการเสริมรอได้เลย (ลูกค้าจะเห็นร้านเมื่ออนุมัติและตั้งราคาแล้ว)" พร้อมลิงก์ไป `/shop/settings` และปิดคิวงาน · `suspended` → หน้า "บัญชีถูกระงับ ติดต่อแอดมิน" · `active` แต่ยังไม่ตั้งราคา → แถบเตือน "ยังไม่ตั้งราคา ลูกค้าจะยังไม่เห็นร้านคุณ" ลิงก์ไปตั้งราคา
- โครงหน้า `DashboardShell`: ชื่อร้าน, สถานะ เปิด/พัก (สวิตช์ "พักรับงาน" เรียก `PUT /shop/profile` — ตัวสวิตช์อยู่บนแถบหัว), เมนู คิวงาน / ตั้งค่า, ปุ่มออกจากระบบ
- **หน้าคิว:** แท็บ/กลุ่มตามสถานะ: "รอยืนยัน" (เด่นสุด มีนับถอยหลังถึง `responseDeadline`, สีแดงเมื่อเหลือ < 3 นาที), "รอชำระเงิน", "ต้องปริ้น" (paid), "กำลังปริ้น", "พร้อมส่งมอบ/รอไรเดอร์", "เสร็จแล้ว" · การ์ดแสดง `orderNo`, เวลาที่สั่ง, จำนวนไฟล์/หน้า, สี/ขาวดำ, วิธีรับ, **เวลาเสร็จประมาณ (ขึ้นสีแดง "เลยเวลา" เมื่อ `estimatedReadyAt` ผ่านไปแล้วและยังไม่ `ready`)** และเรียงกลุ่ม "ต้องปริ้น/กำลังปริ้น" ตามเวลาเสร็จใกล้สุดก่อน · poll ทุก 5–8 วิ และมีเสียง/แถบแจ้งเมื่อมีออเดอร์ใหม่ (เปิดปิดได้; ใช้เสียงสั้น ๆ ที่ไม่ละเมิดลิขสิทธิ์ เช่น สร้างด้วย Web Audio)
- **หน้ารายละเอียด:** ข้อมูลลูกค้า (ชื่อ LINE เท่านั้น ไม่โชว์ user id; **ไม่แสดงชื่อ/เบอร์ผู้รับจัดส่ง และไม่แสดงรหัสรับงาน** — ร้านไม่เห็นตามสัญญา), ไฟล์ทุกไฟล์พร้อมตั้งค่า + 2 ปุ่มต่อไฟล์: **"เปิดดู/พิมพ์"** (`?mode=view` เปิดแท็บใหม่ ร้านสั่งพิมพ์จากเบราว์เซอร์ได้เลย) และ **"ดาวน์โหลด"** (`?mode=download`) · ขอ signed URL ตอนกดแต่ละครั้ง ห้ามเก็บ URL ไว้นาน · ร้านปริ้นซ้ำได้ไม่จำกัด (D20), หมายเหตุ, วิธีรับ/ที่อยู่ส่ง, สรุปราคา:
  - **บริการเสริมที่ลูกค้าเลือก (D22):** แสดงทุกบรรทัดเด่น ๆ (ชื่อ, ไฟล์ที่ใช้, จำนวนชุด, ราคา หรือ "ราคาตามตกลง") เพื่อไม่ให้ร้านลืมทำ · ราคาประเมินที่แสดงรวมบริการที่มีราคาแล้ว ช่อง "ราคาที่ร้านยืนยัน" = ยอดรวมค่าปริ้น + บริการเสริม · ถ้ามีบริการ "ราคาตามตกลง" ช่องนี้บังคับกรอก (เหมือน manual price)
  - ราคาประเมิน (ถ้ามี) + ช่อง "ราคาที่ร้านยืนยัน" (แก้ไขได้ เป็นบาท → แปลงเป็นสตางค์ที่ฟังก์ชันเดียว), ถ้า `requiresManualPrice` ช่องนี้บังคับกรอก มีข้อความ "ออเดอร์นี้เข้าเงื่อนไขส่วนลด กรุณากำหนดราคาเอง"
  - **เวลาเสร็จประมาณ (D19, บังคับเลือกก่อนกด "ยืนยันราคา" ปุ่มจะ disable จนกว่าเลือก):** ตัวเลือกปุ่มกด: "พร้อมรับเลย (~15 นาที)" · "30 นาที" · "1 ชม." · "2 ชม." (นับจากตอนลูกค้าชำระเงิน) และ "วันนี้ก่อนร้านปิด" · "พรุ่งนี้ 12:00" · "กำหนดเอง (เลือกวัน+เวลา)" (เวลาตายตัว) + ช่องหมายเหตุ ≤ 200 ตัวอักษร · แสดงตัวอย่าง "ลูกค้าจะเห็น: …" · ถ้าเวลาตายตัวอยู่นอกเวลาเปิดร้าน ขึ้นคำเตือนสีเหลือง (ไม่บล็อก) · ส่งเป็น `readyInMinutes` หรือ `estimatedReadyAt` อย่างใดอย่างหนึ่ง · เวลาไทย (Asia/Bangkok) ทั้งหมด
  - หลังจ่ายแล้ว (`paid`/`printing`): ปุ่ม "ปรับเวลาเสร็จ" → `POST /shop/orders/:id/eta` (ยืนยันก่อนส่ง: "ลูกค้าจะได้รับแจ้งเตือน")
  - แสดงค่าบริการแพลตฟอร์มที่จะหัก/ลูกค้าจ่ายตามที่ API ให้ (ร้านรู้ว่าตนได้เท่าไร: "คุณจะได้รับ ฿X")
  - ปุ่มตามสถานะ: `submitted` → **ยืนยันราคา** / **ปฏิเสธ** (modal ต้องใส่เหตุผล เลือกด่วน: "เปิดไฟล์ไม่ได้", "ไฟล์มีรหัสผ่าน/ไฟล์เสีย", "ไม่รับงานชุดนี้", "ร้านปิดแล้ว", + พิมพ์เอง) · `paid` → "เริ่มปริ้น" (+ "ปฏิเสธ/คืนเงิน" เมื่อมีปัญหาไฟล์) · `printing` → "ปริ้นเสร็จแล้ว" · `ready` (pickup) → ช่องกรอก **รหัสรับงาน** (ช่องตัวเลข 4 หลัก เปิดแป้นตัวเลขบนแท็บเล็ต; ใส่ผิดซ้ำเกินกำหนดแสดงข้อความ "ลองใหม่อีกครั้งภายหลัง") + "ส่งมอบแล้ว" · `courier_requested|in_transit` → แสดงสถานะรอไรเดอร์ (ร้านไม่ต้องทำอะไร)
  - ทุกปุ่ม: ยืนยันก่อนทำเรื่องที่ย้อนไม่ได้ (ปฏิเสธ/ส่งมอบ), disable ระหว่างส่ง, แสดง toast ผลลัพธ์, จัดการ `ORDER_INVALID_TRANSITION` (สถานะเปลี่ยนไปแล้ว → รีเฟรชข้อมูล + ข้อความ "ออเดอร์นี้เปลี่ยนสถานะแล้ว")
  - แชทกับลูกค้า (คอมโพเนนต์เดียวกับ Y5 แต่ฝั่งร้าน) · ห้องปิดเมื่อออเดอร์จบ (เหมือน Y5) · **ปุ่มตอบด่วนของร้าน** (กดแล้วเติมลงช่องพิมพ์ให้แก้ก่อนส่งได้): "ไฟล์มีรหัสผ่าน ปริ้นให้ไม่ได้ ช่วยส่งไฟล์ใหม่ (สั่งออเดอร์ใหม่) ค่ะ/ครับ" · "เปิดไฟล์ไม่ได้ รบกวนตรวจไฟล์อีกครั้ง" · "งานนี้วันนี้ยังไม่เสร็จ จะเสร็จ…" (ถ้าเลือกเวลาเสร็จแล้วให้ใช้ปุ่ม ปรับเวลาเสร็จ แทน)
