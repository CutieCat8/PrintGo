## 1. ทางเดินหลัก 5 เส้น (Z8)

อุปกรณ์: ลูกค้า = มือถือ LINE จริง · ร้าน/แอดมิน = เบราว์เซอร์คอม

| เส้น | ขั้นตอน | ผลที่ควรเป็น | ผล |
|---|---|---|---|
| **A รับเอง** | ลูกค้าส่งไฟล์ → เลือกร้าน S1 → รับเอง → ส่งออเดอร์ | ร้านเห็นออเดอร์ใหม่ภายใน ≤ 8 วินาที + มี Web Push | - |
| | ร้านยืนยันราคา + เลือกเวลาเสร็จ | ลูกค้าได้ Flex "ใบเสนอราคา" ใน LINE ตัวเลขเป็นบาท (เช่น 23.00 ไม่ใช่ 2300) | - |
| | ลูกค้าจ่าย (QR + สลิป) | สถานะ `paid` · ลูกค้าได้ Flex "ชำระเงินแล้ว" พร้อมรหัสรับงาน 4 หลัก · **ร้านไม่เห็นรหัส** | - |
| | ร้านกด "เริ่มปริ้น" → "พร้อมรับ" | ลูกค้าได้ Flex "กำลังปริ้น" และ "พร้อมรับ" (มีที่อยู่ร้าน) | - |
| | ร้านกรอกรหัสรับงานที่ลูกค้าบอก | `completed` · ผิด 5 ครั้งใน 10 นาที → ถูกจำกัด (D25) | - |
| **B จัดส่ง** | ลูกค้าอนุญาตตำแหน่ง → เลือก "ส่งถึงที่" + ชื่อ/เบอร์ผู้รับ → สั่ง | ใบเสนอราคามีค่าส่ง · ร้านไม่เห็นชื่อ/เบอร์ผู้รับ | - |
| | จ่ายแล้วร้านกด "พร้อม" | ลูกค้าได้ "กำลังหาไรเดอร์" · มีแถว `deliveries` · แอดมินเห็นในหน้าขนส่ง | - |
| | แอดมินอัปเดตสถานะส่ง (manual) → `in_transit` → `completed` | ลูกค้าได้ Flex ตามแต่ละสถานะ (ลิงก์ติดตามถ้ามี) | - |
| **C ร้านปฏิเสธ** | ร้านกด "ปฏิเสธ" (ต้องมีเหตุผล) ก่อนจ่าย | ลูกค้าได้ Flex "ร้านไม่รับออเดอร์" + เหตุผล · ปฏิเสธไม่ได้ถ้าไม่ใส่เหตุผล | - |
| | (เพิ่ม) ร้านปฏิเสธหลังจ่าย | สร้าง `refunds` สถานะ `pending` ให้แอดมินโอนคืน | - |
| **D หมดเวลา** | ส่งออเดอร์แล้วร้านไม่ตอบ 15 นาที (หรือปรับ `SHOP_RESPONSE_MINUTES` ชั่วคราว) | ออเดอร์เป็น `expired` · ลูกค้าได้ Flex "หมดเวลา" | - |
| | ร้านยืนยันราคาแล้วลูกค้าไม่จ่าย 30 นาที | `expired` เช่นกัน | - |
| **E บริการเสริม + ETA + แชท** | สั่งพร้อมบริการเสริมที่ราคาตายตัว | ใบเสนอราคาแสดงบริการเป็นบรรทัด | - |
| | สั่งพร้อมบริการ "ราคาตามตกลง" | `requires_manual_price` · ร้านต้องกรอกราคาก่อนยืนยัน · ระบบไม่ส่งราคาให้ลูกค้าเอง | - |
| | หลังจ่าย ร้านปรับเวลาเสร็จ | ลูกค้าได้ Flex "ปรับเวลาเสร็จ" มีปุ่มเปิดแชท **ไม่มีปุ่มยกเลิก** · การ์ดฝั่งร้านขึ้นแดงเมื่อเลยเวลา | - |
| | ร้านพิมพ์แชทหลายข้อความติดกัน | ลูกค้าได้ push ครั้งเดียว (ไม่ส่งซ้ำทุกข้อความ) · altText เป็น "ร้านมีคำถามเรื่องออเดอร์ PG-xxxx" | - |
| | ลูกค้าตอบแชท | ร้านได้ Web Push + badge + เสียง + ชื่อแท็บเปลี่ยน | - |

## 6. สคริปต์เดโม 5 นาที

เตรียม: reset ข้อมูลทดสอบ · ร้านตัวอย่าง S1 เปิดอยู่และตั้งราคาแล้ว · มือถือลูกค้าเปิด LINE OA · คอมเปิด dashboard ร้านและหน้าแอดมิน (แยก 2 แท็บ/จอ)

| นาที | ทำ | พูด |
|---|---|---|
| 0:00–0:30 | เปิด LINE OA กดเมนู "สั่งปริ้น" | ปัญหา: ไปร้านปริ้นต้องส่งไฟล์ถามราคาหลายร้าน · PrintGo ส่งไฟล์เดียวผ่าน LINE |
| 0:30–1:30 | อัปโหลดไฟล์ ตั้งค่า (สี/ขนาด/ชุด) เลือกร้าน เห็นราคาประมาณและเวลาเสร็จ | เทียบร้านได้ในที่เดียว ราคาคำนวณโปร่งใส |
| 1:30–2:15 | ส่งออเดอร์ → คอมร้านเด้ง + เสียง (และ Web Push ถ้าปิดแท็บ) → ร้านยืนยันราคา เลือกเวลาเสร็จ | ร้านไม่ต้องตอบแชทหลายรอบ ลูกค้าเห็นเวลาเสร็จก่อนจ่าย |
| 2:15–3:00 | มือถือได้ Flex ใบเสนอราคา → กดชำระ → QR → ส่งสลิป | แจ้งเตือนผ่าน LINE ไม่ต้องเปิดแอปใหม่ |
| 3:00–3:45 | ร้านกดปริ้น → พร้อมรับ → มือถือได้ Flex + รหัสรับงาน | ร้านเห็นเฉพาะที่ต้องใช้ ไม่เห็นรหัสรับงาน |
| 3:45–4:30 | ร้านกรอกรหัสรับงาน → เสร็จ · โชว์หน้าแอดมิน: ยอดค้างโอนร้าน + คืนเงิน | แพลตฟอร์มรับเงินแล้วแบ่งให้ร้าน |
| 4:30–5:00 | สรุป: จุดที่เป็น mock (SlipOK, Grab) และแผนต่อ | พูดตรง ๆ ตามหัวข้อ 4 |

## 7. แผนสำรอง

- อัดวิดีโอหน้าจอ flow เต็มไว้ล่วงหน้า (มือถือ + คอมร้านคู่กัน) เก็บไว้ทั้งในเครื่องและ Google Drive
- ถ้า LINE หรือเน็ตมีปัญหา: เปิดวิดีโอ แล้วเล่า flow ตามสคริปต์
- ถ้า Vercel ล่ม: รัน `npm run dev` บนคอม + `NEXT_PUBLIC_USE_MOCK=true` โชว์หน้าจอด้วยข้อมูลตัวอย่าง (ต้องบอกผู้ฟังว่าเป็นโหมดจำลอง)
- เตรียมบัญชีทดสอบและรหัสผ่านไว้ในที่ที่เปิดได้ทันที (ห้ามแปะในสไลด์)
