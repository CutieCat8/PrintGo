# A8 — หน้าตั้งค่าร้าน

หน้าตั้งค่าโปรไฟล์ เวลาเปิด–ปิด ราคาปริ้น และบริการเสริม ใช้ DashboardShell/ToastProvider ของหน้าร้านเดิมและ client API ของ P7 ไม่มี endpoint หรือ dependency เพิ่ม

- เงินรับเป็นข้อความบาท ตรวจรูปแบบก่อนใช้ `parseBahtToSatang` กลาง ราคาปริ้นช่องว่างคือไม่รองรับ บริการราคาตามตกลงส่ง `null` ส่วนลดตามปริมาณต้องให้ร้านกำหนดราคาเอง
- ค่า O8 ใช้เวลาตัดรับงานที่ API คืนมา (ร้านใหม่มี default 30 นาทีจาก P7) ไม่ตั้งค่าทับตอนเปิดฟอร์ม ไม่มีอัปโหลดโลโก้
- ใช้ตำแหน่งปัจจุบันเฉพาะเมื่อกดปุ่ม เติมพิกัดให้ตรวจสอบก่อนบันทึก
- การจัดลำดับบริการใช้ PUT รายรายการตาม API เดิม ไม่ atomic หากล้มเหลวระหว่างทางจะอ่านรายการล่าสุดและแสดงข้อผิดพลาด
- สถานะพักรับงานที่ยังไม่ได้แก้ในฟอร์มตาม `shopMe` เพื่อไม่ส่งค่าเก่าทับสวิตช์บน header
- `instant = false` เฉพาะ settings layout/pages เพราะ ShopFrame รอข้อมูลบัญชีผ่าน client ก่อนแสดง children ตามคู่มือ Next.js ในโปรเจกต์

## การตรวจสอบ

- lint, typecheck และ Vitest; tests ใน `_lib/forms.test.ts` ตรวจเงิน/ขอบเขตข้อมูลกับ schema P7, เวลาปิด 24:00/ไม่ข้ามวัน, mapping 422 และ regression สถานะพักรับงาน
- integration ผ่าน API ในหน่วยความจำ: เปลี่ยนราคาแล้ว shop list/estimate เปลี่ยน เพิ่ม/แก้/ปิด/ลบบริการ และราคาตามตกลง/ส่วนลดไม่คืนยอดให้จ่ายอัตโนมัติ นี่เป็น mock ไม่ใช่ Supabase
- Chrome บน dev server: เปิดทั้ง 4 หน้าและตรวจ layout ที่ viewport 1024px; เพิ่มบริการสันเกลียวแบบราคาตามตกลง เห็นช่องราคาปิด ตัวอย่างข้อความ รายการใหม่และ toast สำเร็จในโหมด mock ไม่เรียกตำแหน่งจริง

ก่อนใช้จริงต้องทดสอบบัญชีร้าน pending/active กับ P7 และ Supabase พร้อมบัญชีลูกค้าตรวจรายการร้าน/estimate ข้าม session รวมถึงกรณี API ตอบ 422/network failure จริง ข้อมูล mock จะหายเมื่อ reload และไม่ใช่หลักฐานว่าบันทึกฐานข้อมูลสำเร็จ
