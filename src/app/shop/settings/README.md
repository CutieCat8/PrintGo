# A8 — หน้าตั้งค่าร้าน

หน้าตั้งค่าโปรไฟล์ เวลาเปิด–ปิด ราคาปริ้น และบริการเสริม ใช้ DashboardShell/ToastProvider ของหน้าร้านเดิมและ client API ของ P7 ไม่มี endpoint หรือ dependency เพิ่ม

- เงินรับเป็นข้อความบาท ตรวจรูปแบบก่อนใช้ `parseBahtToSatang` กลาง ราคาปริ้นช่องว่างคือไม่รองรับ บริการราคาตามตกลงส่ง `null` ส่วนลดตามปริมาณต้องให้ร้านกำหนดราคาเอง
- ค่า O8 ใช้เวลาตัดรับงานที่ API คืนมา (ร้านใหม่มี default 30 นาทีจาก P7) ไม่ตั้งค่าทับตอนเปิดฟอร์ม ไม่มีอัปโหลดโลโก้
- ใช้ตำแหน่งปัจจุบันเฉพาะเมื่อกดปุ่ม เติมพิกัดให้ตรวจสอบก่อนบันทึก
- การจัดลำดับบริการใช้ PUT รายรายการตาม API เดิม ไม่ atomic หากล้มเหลวระหว่างทางจะอ่านรายการล่าสุดและแสดงข้อผิดพลาด
- สถานะพักรับงานที่ยังไม่ได้แก้ในฟอร์มตาม `shopMe` เพื่อไม่ส่งค่าเก่าทับสวิตช์บน header
- `instant = false` เฉพาะ settings layout/pages เพราะ ShopFrame รอข้อมูลบัญชีผ่าน client ก่อนแสดง children ตามคู่มือ Next.js ในโปรเจกต์

## การตรวจสอบ

- lint, typecheck และ Vitest; tests ใน `_lib/forms.test.ts` ตรวจเงิน/ขอบเขตข้อมูลกับ schema P7, เวลาปิด 24:00/ไม่ข้ามวัน, mapping 422 และ regression สถานะพักรับงาน
- integration ผ่าน API ในหน่วยความจำ: เปลี่ยนราคาแล้ว shop list/estimate เปลี่ยน เพิ่ม/แก้/ปิด/ลบบริการ และราคาตามตกลง/ส่วนลดไม่คืนยอดให้จ่ายอัตโนมัติ นี่เป็น mock ไม่ใช่ Supabase
- Chrome บน dev server: เปิดทั้ง 4 หน้าและตรวจ layout ที่ viewport 1024px; เพิ่มบริการสันเกลียวแบบราคาตามตกลง เห็นช่องราคาปิด ตัวอย่างข้อความ รายการใหม่และ toast สำเร็จในโหมด mock ไม่เรียกตำแหน่งจริง

ผล mock เดิมไม่ใช่หลักฐานบันทึก DB ส่วนผล Supabase จริงเพิ่มเติมอยู่ด้านล่าง

## ผล PrintGo-dev เพิ่มเติม — 14 พ.ย. 2026

- ร้านและ admin ใช้บัญชีสมมติชั่วคราวกับ Supabase session จริง ลูกค้าใช้ development identity อีกบัญชี ไม่ใช่ LINE/LIFF login จริง
- ร้าน pending บันทึก profile (cutoff 45 นาที), เวลา 7 วัน และราคาต่อหน้า 200 สตางค์ได้ อ่านกลับจาก API/DB; ร้านยังไม่แสดงให้ลูกค้าจน admin อนุมัติ
- หลังอนุมัติ ลูกค้าเห็นราคา 200 สตางค์ งาน 10 หน้าได้ total 2300; ร้านแก้ราคาเป็น 300 แล้ว list/estimate ได้ total 3300
- ผู้ใช้ยืนยันบันทึก “ขาวดำ · A4 · ด้านเดียว” เป็น 3.50 บาทผ่าน browser และรีโหลดแล้วยังคงเดิม ผู้ช่วยตรวจอีกครั้งผ่าน session ร้านและ customer API ได้ราคา 350 สตางค์, estimated print 3500 และ total 3800 จึงเป็นหลักฐาน UI ที่ผู้ใช้รายงานร่วมกับ API จริง ไม่ใช่ผู้ช่วยควบคุม browser สำเร็จ (เครื่องมือขึ้น cgWindowNotFound/browser host unavailable)
- สร้างบริการราคาคงที่/ราคาตามตกลงขณะ pending; หลัง active ขณะราคาปริ้นยังเป็น 300 สตางค์/หน้า แก้บริการเป็น 700 สตางค์แล้ว estimate รวม 3000 + 700 + ค่าบริการขั้นต่ำ 300 = 4000; ปิดบริการแล้ว list ไม่แสดงและ estimate ที่ส่ง serviceId เดิมได้ 422
- บริการราคาตามตกลงทำให้ requiresManualPrice=true, estimatedPrintSatang/totalSatang=null; tier จำนวนหน้า 10 ก็ได้ manual/null ไม่ส่งยอดให้จ่ายอัตโนมัติ
- เพิ่มและลบบริการผ่าน API แล้วอ่านกลับไม่พบรายการ; พักร้านแล้ว customer list แสดง isPaused=true และคืนค่าเดิมก่อนจบรอบ
- ส่ง profile พิกัดผิด, ชั่วโมงวันซ้ำ, ราคาสตางค์ไม่ใช่จำนวนเต็ม และชื่อบริการเกิน 60 ตัวอักษร ได้ 422 จริง
- ระงับร้านผ่าน A5 แล้ว cookie ร้านเรียก settings ได้ 403; ล้าง fixture ทั้งหมดและ auth users/profiles ชั่วคราว 2 บัญชีพร้อมหยุดตัวช่วย session แล้ว
- ยังไม่ได้ทดสอบ UI ทุกฟอร์มด้วย session จริง, network failure ระหว่างบันทึก, geolocation จริง, การส่งอีเมล login และ customer LIFF จริง ผล UI ที่ 1024px เดิมยังเป็นรอบ mock
- ใช้ O8 โดยร้านทดสอบเลือก cutoff 45 นาทีเอง; ไม่มี default/dependency/schema ใหม่ และไม่ได้แก้ production Supabase
