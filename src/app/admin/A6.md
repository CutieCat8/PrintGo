# A6 — ตรวจสลิปและออเดอร์แอดมิน

## ส่วนที่ทำแล้ว

- `/admin/payments` แสดงสลิปรอตรวจ เลขออเดอร์ ยอดสลิป/ยอดออเดอร์ เวลา และภาพจาก signed URL อายุ 120 วินาที อัปเดตทุก 30 วินาที
- อนุมัติผ่าน `finalizePayment()` ของ A3 เพื่อบันทึก verified/paid/settlement ใน transaction เดียวกัน การอนุมัติซ้ำใช้ผลเดิม
- ปฏิเสธพร้อมเหตุผลผ่าน `reviewPayment()` และ RPC ที่ล็อก shop → order → payment เช่นเดียวกับ finalizer ส่ง `payment_rejected` เฉพาะเมื่อเปลี่ยนจริง
- สลิปของออเดอร์หมดเวลาจะแสดงคำเตือนและปุ่มสร้างรายการคืนเงิน แอดมินต้องยืนยันรับเงินจริงและกรอกเหตุผล
- คืนเงินสลิปหมดอายุผ่าน `expireIfDue()`/`transition()` ก่อน RPC ตรวจสถานะซ้ำใต้ lock บันทึก payment verified โดย admin และ refund pending พร้อมกัน ออเดอร์ยัง expired ไม่มี settlement การเรียกซ้ำไม่เพิ่ม refund
- `/admin/orders` ค้นหาเลขออเดอร์/ชื่อร้าน กรองสถานะ และแสดงสลิปรอตรวจ/ร้านไม่ตอบ/งานพร้อมรับและจัดส่งค้าง
- เกณฑ์ไฮไลต์งานจัดส่งค้างใช้ `updatedAt` เกิน 24 ชั่วโมงเป็นตัวช่วยแอดมิน เลือกให้สอดคล้องกับงาน ready ค้างใน D26 ต้องให้เจ้าของงานตรวจเกณฑ์นี้
- `/admin/orders/[id]` แสดงราคา ไฟล์/บริการ ผู้รับ ที่อยู่ สถานะการจัดส่ง และเหตุผลดำเนินการ เก็บประมาณราคา/ราคาบริการของออเดอร์ manual ที่ยัง submitted สำหรับ admin
- ยกเลิกออเดอร์ที่จ่ายแล้วพร้อมคืนเต็มหรือบางส่วนผ่าน transition ยอดเป็น integer satang ตรวจรูปแบบบาทก่อนแปลง ปฏิเสธ comma ผิดรูปแบบและยอดเกินที่จ่าย
- ปิดงาน ready เฉพาะ pickup ผ่าน transition โดย admin ต้องระบุเหตุผล เก็บใน rejectReason ของออเดอร์ ร้านใช้เส้นทางเดิมได้โดยไม่ต้องระบุเหตุผล
- ทุกหน้าเรียก guard ฝั่ง server ทุก API ตรวจ requireAdmin ก่อนข้อมูล mutation ตรวจ origin และตอบ private/no-store

## การทดสอบ

- lint/typecheck ผ่าน
- tests ทั้งโปรเจกต์แบบปกติ 1043 ผ่าน / 15 ข้าม (14 PostgreSQL opt-in และ 1 manual QR preview)
- เมื่อเปิด PostgreSQL opt-in: 1057 ผ่าน / 1 ข้าม รวมการทดสอบ finance RPC จริง 14 ข้อบน PostgreSQL 17 ใน Docker แยก network ใช้ฐานข้อมูลสมมติที่สร้างและลบทุกรอบ
- PG ครอบคลุม concurrent refund/replay, rollback payment เมื่อ insert refund ล้ม, approve ชน reject มีผู้ชนะเดียว, ยอดไม่ตรง, สถานะผิด และสิทธิ์ service_role
- route tests ใช้ requireAdmin จริงใน dev/test แต่ mock operations จึงวัดสิทธิ์/input/dispatch ส่วน operations/domain tests ใช้ mock DB/RPC และมี regression money/presenter/transition
- HTTP จริงบน Next dev กับ Supabase dev: GET admin payments/orders ได้ anonymous 401, customer 403, dev admin 200
- reviewer ตรวจและแก้ blocker เรื่อง comma ในยอดคืนแล้ว ตรวจซ้ำไม่มี blocker เพิ่ม
