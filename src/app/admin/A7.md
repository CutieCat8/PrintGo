# A7 — จัดส่งด้วยมือและภาพรวม

## สิ่งที่เพิ่ม

- `/admin/deliveries`: คิวเริ่มที่ pending_admin เลือก booked/in_transit/failed หรือทั้งหมดที่ยังไม่จบได้ แสดงร้าน จุดส่ง ชื่อ/เบอร์ผู้รับ พิกัด ปุ่มคัดลอก และ Maps link
- ใช้ `GET /api/admin/orders?queue=delivery` อ่านเฉพาะ manual delivery ที่ออเดอร์ courier_requested/in_transit ด้วย keyset pagination ไม่ส่งข้อมูลผู้รับให้ shop/customer endpoint ใหม่
- `POST /api/admin/orders/:id/delivery` ตรวจ admin/origin/UUID/strict input และ provider=manual ก่อนเรียก applyDeliveryUpdate; ไม่รับยอดรวมออเดอร์จาก client
- manual applyDeliveryUpdate เรียก transitionManualDelivery ที่ขอบเขต transition.ts ก่อน RPC ใหม่ ส่วน Grab webhook เดิมยังใช้เส้นทางเดิม ไม่อ้างว่า A7 เชื่อม Grab API
- ลำดับ pending_admin → booked → in_transit → delivered หรือ booked/in_transit → failed; failed เรียกใหม่ด้วย booked ได้ ออเดอร์ in_transit ไม่ย้อนกลับเมื่อเรียกใหม่
- in_transit เปลี่ยนออเดอร์ courier_requested → in_transit; delivered เปลี่ยน in_transit → completed พร้อม completed_at ใน transaction เดียวกับ delivery
- ล็อก shop → order → delivery สอดคล้องธุรกรรมยกเลิก/คืนเงิน การเรียกซ้ำสถานะเดิมและ metadata เดิมไม่เขียน timestamp ใหม่ สถานะเดิมแต่ข้อมูลต่างกันคืน 409 การแก้ข้อมูลทำพร้อมขั้นถัดไป
- ค่าส่งจริงแปลงข้อความบาทเป็นจำนวนเต็มสตางค์ ตรวจ comma/ทศนิยม/ขอบเขต DB และยอม 0; เว้นว่างไม่เขียนทับของเดิม บันทึกเฉพาะ deliveries.fee_satang ไม่ปรับ total_satang ที่ลูกค้ายืนยันแล้ว
- failed มีลิงก์รายละเอียดออเดอร์เพื่อใช้การยกเลิก/คืนเงิน A6 ไม่สร้าง refund อัตโนมัติจาก failed
- `GET /api/admin/overview`: ordersToday นับออเดอร์สร้างวันนี้ตามเวลาไทย; completedToday นับงาน completed ในกลุ่มที่สร้างวันนี้ (ใช้หารอัตราสำเร็จของกลุ่มเดียวกัน) ค่าบริการวันนี้นับ completed_at วันนี้ ส่วนค่าบริการทั้งหมดนับเฉพาะ completed
- GET สำเร็จตอบ private/no-store; หน้าและ API ตรวจสิทธิ์แยกกัน

Maps URL ใช้ api=1 และ URLSearchParams ตาม [เอกสาร Google Maps URLs](https://developers.google.com/maps/documentation/urls/get-started) ที่ตรวจ 13 พ.ย. 2026 ส่งเฉพาะพิกัดเมื่อผู้ใช้กดลิงก์ ไม่มีการฝังแผนที่โหลดข้อมูลเอง
