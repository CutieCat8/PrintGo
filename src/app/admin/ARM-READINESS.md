## ลำดับดำเนินการ

1. ให้ทีมรีวิว PR #18 → #20 → #23 ตามเจ้าของไฟล์ ทั้งสาม Ready for review แล้ว
2. หลังรีวิว merge ทีละ PR ปรับฐาน PR ถัดไปเป็น main และตรวจ diff/CI ก่อน merge ทุกครั้ง
3. ตรวจ migration ที่ target dev มีอยู่จริงก่อนใช้โค้ด A6 ไม่ db push แบบเดาประวัติ และไม่แก้ production จากรายการนี้
4. นำ A7 ให้ซี/พลุรีวิวส่วนกลางและ migration แล้วทดสอบ dev พร้อมทำ A5/A8 live integration ที่ยังขาด

5. ทดสอบรวมด้านล่างบน dev และบันทึกผลจริงก่อนปิดเกณฑ์ทั้งหมด

## รายการทดสอบรวมหลัง merge

เตรียม dev ที่ระบุชัดเจน บัญชีลูกค้า/ร้าน/admin แยกสิทธิ์ และข้อมูลติดป้ายตัวอย่างสมมติ
ตรวจ configuration โดยไม่ส่ง key/token/เลขบัญชีในแชทหรือ commit
ใช้ manual review ตาม O9 และคืนเงินด้วยมือตาม O4; การเปลี่ยนเป็น SlipOK จริงเป็นรอบทดสอบแยก

- [ ] A5/A8: ร้าน pending ตั้งโปรไฟล์/เวลาครบ/ราคา/บริการได้ แต่ยังไม่โผล่ให้ลูกค้า; admin อนุมัติแล้วจึงโผล่เมื่อมีราคา
- [ ] A8: แก้ราคาและบริการแล้วลูกค้าอีก session เห็น estimate ใหม่; ราคาตามตกลง/ส่วนลดบังคับร้านกำหนดราคา ไม่ให้จ่ายอัตโนมัติ
- [ ] A1/A3: สร้างออเดอร์ ร้านยืนยันราคา ลูกค้าเห็น QR ผู้รับ/ยอดตรง total_satang และใช้งานที่ 360px ได้
- [ ] A2/A3/A6: ส่งภาพสมมติใน manual flow → pending_review → admin อนุมัติ → paid/verified และ settlement เพียงหนึ่งรายการ; หน้าแสดงรหัสรับงานเฉพาะลูกค้าที่รับเอง
- [ ] A3/A6: ปฏิเสธพร้อมเหตุผล → ลูกค้าส่งใหม่ได้; ทดสอบหมดเวลาและสลิปซ้ำไม่สร้างเงิน/settlement ซ้ำ
- [ ] A6/A4: ปิดงานรับเอง ready → completed แล้วจึงอยู่คิวโอนให้ร้าน; บันทึกรายการหนึ่งแล้วเหลือยอดอื่นถูกต้อง เรียกซ้ำไม่เปลี่ยน timestamp/หลักฐาน
- [ ] A6/A4: ยกเลิกคืนบางส่วนหรือคืนเงินสลิปหมดอายุ → refund pending หนึ่งรายการ; ห้ามเกินยอด บันทึกคืนแล้วสถานะ paid และยอดคงถูกต้อง
- [ ] A7 หลังพัฒนา: ร้านพร้อมส่ง → คิว admin → booked/in_transit/delivered → completed; ค่าส่งจริงเป็นสตางค์ และ failed ให้ตัดสินใจต่อได้ตาม task
- [ ] A7 หลังพัฒนา: ยอดรายได้จาก completed ตรง DB; ไม่รวม cancelled/ยังไม่เสร็จ
- [ ] LINE จริง: ลูกค้าล็อกอิน LIFF และได้รับข้อความสถานะจริง แยกผลนี้จาก dev auth/notify stub
- [ ] สิทธิ์: anonymous/admin/shop/customer ถูกจำกัดตามบทบาท ร้านไม่เห็น pickupCode หรือข้อมูลผู้รับจัดส่ง และข้ามร้าน/ข้ามลูกค้าไม่ได้
- [ ] ตรวจ UI paid/all และรีโหลดว่ายังแสดงผลที่บันทึกแล้วโดยไม่มีปุ่มบันทึกซ้ำ
- [ ] ล้างข้อมูล/ไฟล์และบัญชีสมมติของรอบทดสอบ ตรวจว่าไม่เหลือสิทธิ์ admin ชั่วคราว แล้วเก็บผล pass/fail และข้อผิดพลาดโดยไม่มีข้อมูลลับ
